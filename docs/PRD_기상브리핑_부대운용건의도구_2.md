# PRD: 보병대대 기상 브리핑 자동화 및 부대운용 건의 도구 (시제품)

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.2 (MVP 시제품 + Gemini API 연동 준비) |
| 작성일 | 2026-11-02 (v0.2 수정: 2026-11-03) |
| 작성자 | 류지만 |
| 대상 | 보병대대 기상 담당자 1명 (시제품) |

| 실행 환경 | 인트라넷 PC, 웹브라우저, 단일 HTML 파일 (서버 없음, 오프라인 동작) |

## 1. 배경 (문제 정의)

- **자료 출처가 두 망으로 나뉘어 있음**
  - 일반 기상: 인터넷의 민간기상 자료 → 망연계 자료전송 시스템으로 **웹페이지 캡처 이미지**를 인트라넷에 반입
  - 항공 기상: 인트라넷의 공군기상전대 **기상전문**(METAR/TAF 형식)
- **문서화가 전부 수작업**: 두 자료를 보고 pptx, 한글 문서에 일일이 옮겨 적음
- **작성 빈도가 높음**
  - 평시: 하루 2회 (아침, 저녁)
  - 기상이변 시(폭설, 폭염, 폭우, 혹한, 태풍, 황사 등): **2시간 단위** 작성
- **부대운용 판단에 정해진 기준이 없음**: 담당자 경험에 의존해서 판단 결과가 사람마다 다를 수 있고 근거를 남기기 어려움
- **지난 브리핑 이력을 다시 보기 어려움**

## 2. 목표와 비목표

### 목표
1. 06:00 전문 수신부터 07:00 문서 완성까지 걸리는 **작성 시간 단축** (목표: 입력부터 산출물까지 5분 이내)
2. 공개 기준(기상청 특보 기준 등)에 근거한 **일관된 부대운용 권고** 제공 (정상, 조정, 중단)
3. 브리핑 **이력 저장 및 재조회**

### 비목표 (시제품 범위 밖)
- 로그인, 권한 관리, 결제
- 서버 배포, 다중 사용자 동시 사용 (200명 조작, 1,800명 열람은 확장 단계)
- 캡처 이미지 자동 판독(OCR)
- 한글(hwp/hwpx) 파일 직접 생성
- ~~생성형 AI(LLM) 연동~~ → **v0.2: Gemini API 연동을 선택 기능으로 포함** (16장). 단, 네트워크 경로와 보안 승인이 확인돼야 켤 수 있음
- 인터넷 자료 자동 수집 (망분리 규정상 불가)

## 3. 사용자

| 구분 | 인원 (최종 목표) | 시제품 | 역할 |
|---|---|---|---|
| 조작자 (기상 담당) | 약 200명 | **1명 (보병대대 기상 담당)** | 자료 입력, 문서 생성, 운용 건의 |
| 열람자 (지휘관, 참모) | 약 1,800명 | 출력물(pptx, 인쇄본)로 간접 사용 | 브리핑 수령, 운용 결심 |

## 4. 핵심 시나리오 (아침 브리핑)

> **06:00** 기상 담당자가 공군기상전대 기상전문을 받고, 망연계로 민간기상 웹페이지 캡처를 받는다.
> **06:10** 도구(HTML 파일)를 열어 전문을 붙여넣고 캡처 이미지를 첨부한다. 캡처를 옆에 띄워 둔 채 핵심 수치 10여 개를 입력한다.
> **06:20** 도구가 전문을 자동 해석하고, 입력 수치를 기준표와 비교해 특보 및 악기상 여부와 **부대활동별 권고(정상, 조정, 중단)와 근거**를 보여준다.
> **06:30** 담당자가 권고 문구를 확인하고 필요하면 수정한 뒤 저장한다. **pptx 내보내기**와 **인쇄(PDF)**를 실행한다.
> **07:00** 문서화 완료.
> **08:00** 브리핑 화면으로 기상을 가시화하고 부대운용을 건의한다. (예: "14시 이후 강풍 주의보 수준 예상 → 사격훈련 조정, 특보 발령 시 야외활동 중단")

**기상이변 시**: 같은 흐름을 2시간마다 반복하고, 회차별로 이력에 쌓아 직전 회차와 비교한다.

## 5. MVP 핵심 기능 (3개)

### F1. 기상 자료 입력 및 자동 해석
- 공군 **기상전문(METAR/TAF) 붙여넣기 → 자동 해석**
  - 풍향, 풍속, 돌풍, 시정, 일기현상(비, 눈, 뇌우, 안개, 황사 등), 운고, 기온, 이슬점, 기압
  - UTC를 KST(+9)로 변환해서 표시
  - 해석 실패한 부분은 원문 그대로 표시하고 수동 수정 가능
- **민간기상 캡처 이미지 첨부 및 미리보기** (판독은 하지 않음)
- **핵심 수치 수동 입력 폼**: 캡처를 보면서 입력
  - 최저/최고 기온, 최고 체감온도, 강수확률, 예상 강수량(3h/12h), 예상 적설(24h), 최대 풍속/순간풍속, 미세먼지(PM10), 하늘상태
  - 현재 발령 중인 기상특보 (체크박스: 종류 × 주의보/경보)
- 회차 선택: 아침, 저녁, 기상이변(시각 지정)

### F2. 부대운용 권고 (규칙 기반)
- 입력값과 해석값을 **기준표(7장)**와 비교해서 활동별 상태 산출
  - 🟢 정상, 🟡 조정 (악기상 또는 특보 기준 근접), 🔴 중단 (특보 발령 또는 특보 기준 도달)
- 각 권고에 **근거 기준 표시** (예: "순간풍속 22m/s ≥ 강풍주의보 기준 20m/s")
- 권고 문구는 템플릿으로 자동 생성하고 담당자가 **수정 가능**
- 기준표는 설정 화면에서 **부대별로 수정 가능** (기본값 = 7장 초안)
- 평가 대상 부대활동 (기본값, 추가/삭제 가능)
  1. 야외 교육훈련
  2. 사격
  3. 행군
  4. 차량 운행
  5. 경계근무
  6. 체력단련
  7. 헬기 지원 (항공기상 연계)

### F3. 브리핑 산출물 생성 및 이력 관리
- **브리핑 화면(08:00 가시화용)**: 시간대별 기온, 풍속, 강수 그래프 / 특보 배너 / 활동별 신호등 표
- **pptx 내보내기** (표지, 기상 현황, 시간대별 예보, 부대운용 건의, 총 4장 내외)
- **인쇄 화면** (브라우저 인쇄 → PDF 저장, 한글 문서 첨부용)
- **한글용 표 복사** 버튼 (한글에 붙여넣기 좋은 표 형식으로 클립보드 복사)
- **이력 저장**: 회차별 자동 저장, 목록 조회, 다시 열기, 직전 회차와 비교
- **백업**: 이력 전체를 JSON 파일로 내보내기/불러오기 (PC나 브라우저 교체 대비)

## 6. 화면 구성 (3개)

| # | 화면 | 하는 일 | 주요 요소 |
|---|---|---|---|
| 1 | **입력** | 자료를 넣고 해석 결과를 확인 | 회차 선택, 전문 입력창 + 해석 결과표, 캡처 첨부 및 미리보기, 핵심 수치 폼, 특보 체크박스, [판단 실행] 버튼 |
| 2 | **브리핑** | 08:00 브리핑 가시화, 운용 건의, 산출물 생성 | 특보 배너, 요약 카드, 시간대별 그래프, 활동별 신호등 표(근거 포함, 문구 수정), [저장] [pptx] [인쇄] [한글용 복사] |
| 3 | **이력** | 지난 브리핑 조회 및 백업 | 날짜/회차/특보 여부 목록, 필터, 다시 열기, 직전 회차 비교, [백업 내보내기] [불러오기] |

> 기준표 수정은 별도 화면 대신 이력 화면의 **설정 탭**으로 넣는다.

## 7. 부대운용 판단 기준표 (초안, 참고용)

> ⚠️ 아래 수치는 **공개 자료 기반 초안**이며 실제 적용 전 **부대 지휘관 승인**과 **최신 기상청 기준 재확인**이 필요하다. 도구에서 수정 가능하다.

### 7-1. 기상청 기상특보 발표기준 (육상, 요약)

| 현상 | 주의보 | 경보 |
|---|---|---|
| 폭염 | 일 최고체감온도 33℃ 이상 2일 이상 지속 예상 | 일 최고체감온도 35℃ 이상 2일 이상 지속 예상 |
| 한파 (10~4월) | 아침 최저기온 -12℃ 이하 2일 이상 지속 예상, 또는 전날보다 10℃ 이상 하강해 3℃ 이하이고 평년보다 3℃ 낮을 때 | 아침 최저기온 -15℃ 이하 2일 이상 지속 예상, 또는 전날보다 15℃ 이상 하강해 3℃ 이하이고 평년보다 3℃ 낮을 때 |
| 호우 | 3시간 60mm 이상 또는 12시간 110mm 이상 예상 | 3시간 90mm 이상 또는 12시간 180mm 이상 예상 |
| 대설 | 24시간 신적설 5cm 이상 예상 | 24시간 신적설 20cm 이상 예상 (산지 30cm) |
| 강풍 | 풍속 14m/s 이상 또는 순간풍속 20m/s 이상 (산지 17/25) | 풍속 21m/s 이상 또는 순간풍속 26m/s 이상 (산지 24/30) |
| 태풍 | 태풍으로 강풍, 호우 등이 주의보 기준에 도달 예상 | 태풍으로 강풍 경보 기준 도달 또는 총강우량 200mm 이상 예상 |
| 황사 | (해당 없음) | 황사로 1시간 평균 PM10 800㎍/㎥ 이상 2시간 이상 지속 예상 |

### 7-2. 판단 규칙 (기본값)

| 상태 | 조건 |
|---|---|
| 🔴 중단 | 해당 지역 **경보 발령**, 또는 입력값이 **경보 기준 도달**, 또는 뇌우(TS) 관측/예보 시 야외활동 |
| 🟡 조정 | **주의보 발령**, 또는 입력값이 **주의보 기준의 80% 이상**, 또는 아래 활동별 악기상 조건 해당 |
| 🟢 정상 | 위 조건 없음 |

### 7-3. 활동별 악기상 조건 (초안)

| 활동 | 조정 조건 (예시) | 중단 조건 (예시) |
|---|---|---|
| 야외 교육훈련 | 체감온도 31℃ 이상, 기온 -10℃ 이하, 강수 중 | 폭염/한파/호우/대설/강풍/태풍/황사 특보 |
| 사격 | 시정 1km 미만, 풍속 10m/s 이상, 강수 중 | 뇌우, 시정 0.5km 미만, 강풍 특보 |
| 행군 | 체감온도 31℃ 이상, 기온 -10℃ 이하, 적설 중 | 폭염/한파/대설/호우 특보 |
| 차량 운행 | 시정 1km 미만, 적설·결빙 예상(기온 0℃ 이하 + 강수) | 대설/호우/태풍 경보, 시정 0.2km 미만 |
| 경계근무 | 체감온도 31℃ 이상 또는 -10℃ 이하 → 근무시간 단축, 보호장구 | (중단 없음, 형태 조정) |
| 체력단련 | 체감온도 31℃ 이상, PM10 150㎍/㎥ 이상 | 폭염 특보, 황사 경보, PM10 300 이상 |
| 헬기 지원 | 시정 5km 미만 또는 운고 1,500ft 미만, 풍속 15kt 이상 | 시정 1.6km 미만 또는 운고 500ft 미만, 뇌우, 돌풍 25kt 이상 |

> 온열손상 예방 기준(온열지수/WBGT 단계별 훈련 통제)은 **부대 하달 지침 수치**를 확인해서 체감온도 기준을 대체하거나 추가한다.

## 8. 데이터

### 8-1. 저장 위치
- 브라우저 내부 저장소(IndexedDB) — 해당 PC, 해당 브라우저에만 저장
- JSON 백업 파일로 내보내기/불러오기

### 8-2. 데이터 구조 (요약)

```
Briefing (브리핑 1회차)
├─ id, 작성일시, 회차유형(아침/저녁/이변), 대상시각, 작성자
├─ rawMetar / rawTaf          : 전문 원문
├─ parsed                     : 해석 결과 (시각별 풍향·풍속·돌풍·시정·현상·운고·기온)
├─ captureImage               : 민간 캡처 이미지 (축소 저장, 선택)
├─ civilInput                 : 수동 입력 수치 (기온, 체감, 강수, 적설, 풍속, PM10, 하늘)
├─ activeWarnings[]           : 발령 특보 (종류, 단계)
├─ recommendations[]          : 활동별 {활동명, 상태, 근거, 권고문구(수정본)}
└─ memo                       : 담당자 비고

Settings (설정)
├─ unitName, 지역(육상/산지)
├─ activities[]               : 평가 대상 활동 목록
└─ thresholds                 : 7장 기준표 (수정 가능)
```

## 9. 기술 구성

| 항목 | 선택 | 이유 |
|---|---|---|
| 형태 | **단일 HTML 파일** (CSS, JS, 라이브러리 모두 포함) | 서버 승인 없이 PC에서 바로 실행, 오프라인 동작 |
| 전문 해석 | 자체 METAR/TAF 파서 (JS) | 외부 의존 없음 |
| 그래프 | 경량 차트 라이브러리 인라인 포함 (또는 SVG 직접 그림) | 오프라인 |
| pptx 생성 | PptxGenJS 인라인 포함 | 브라우저만으로 pptx 생성 |
| 저장 | IndexedDB + JSON 백업 | 서버 없이 이력 유지 |
| 판단 엔진 | 규칙 기반 (기준표 비교) = **안전 하한선** | 근거 설명 가능, AI 없이도 동작 |
| AI 조언 | **Gemini API** (`gemini_advisor.js`, 선택 기능) | 상황 설명형 조언, 시간대별 위험 구간 제시 |

## 10. 제약 및 전제

- 로그인, 결제, 서버 없음
- 인터넷 연결 없이 동작 (외부 CDN 호출 금지)
- 인트라넷 PC 설치/반입 승인 절차는 사용자가 별도로 진행
- 이력은 PC 브라우저에 귀속되므로 **정기 백업 필수**
- 입력 자료에 비밀 등급 정보가 포함될 경우 PC 보안 규정을 따름
- 권고는 **참모 건의를 돕는 참고 정보**이며 최종 결심은 지휘관

## 11. 완료 기준 (Definition of Done)

- [ ] 전문을 붙여넣고 핵심 수치를 입력하면 **5분 안에** 브리핑 화면과 pptx가 나온다
- [ ] 전문 해석 결과(풍속, 돌풍, 시정, 현상, 운고, 기온)가 원문과 일치한다 (샘플 전문 5건 이상 검증)
- [ ] 특보 발령 또는 경보 기준 도달 시 해당 활동이 **자동으로 '중단'**, 주의보·악기상 시 **'조정'**으로 표시되고 **근거가 함께** 나온다
- [ ] 권고 문구를 수정해서 저장할 수 있다
- [ ] pptx 파일이 열리고, 인쇄 화면이 A4 1~2장으로 깔끔하게 나온다
- [ ] 저장한 브리핑을 이력에서 **다시 열고**, 직전 회차와 비교할 수 있다
- [ ] 백업 내보내기 → 브라우저 데이터 삭제 → 불러오기 후 이력이 복원된다
- [ ] 인터넷이 끊긴 PC에서 **HTML 파일 하나로** 모든 기능이 동작한다

## 13. 남은 확인 사항 (개발 전후로 확인)

1. **공군 기상전문 실제 형식**: METAR/TAF 표준인지, 부대 고유 형식이 섞여 있는지 (비식별 샘플 1~2건 있으면 파서 정확도가 올라감)
2. **pptx 양식**: 기존 부대 브리핑 템플릿(색상, 로고, 장 구성)이 있는지
3. **활동별 기준 수치**: 7-3 초안을 부대 지침(특히 온열지수 단계)에 맞춰 조정
4. **지역 구분**: 대대 위치가 산지 기준 적용 대상인지
5. **최신 특보 기준 재확인**: 기상청 기준 개정 여부 확인

## 16. Gemini API 연동 (v0.2 추가)

### 16-1. 역할 분담
| 구분 | 규칙 엔진 (기준표) | Gemini |
|---|---|---|
| 위치 | 필수, 항상 동작 | 선택, 켜고 끌 수 있음 |
| 하는 일 | 활동별 정상/조정/중단 판정 | 요약, 주요 위험, 활동별 건의 문구, 적용 시간대, 불확실성 |
| 단계 결정 | **최종 하한선** | 단계 **상향만 가능**, 하향 제안은 무시 |
| 실패 시 | — | 규칙 결과만으로 브리핑 계속 |

### 16-2. ⚠️ 결정 필요: 어디서 Gemini를 호출할까 (가장 중요)
Gemini는 인터넷 서비스라서 **인트라넷 PC에서 바로 호출할 수 없을 가능성이 높다.** 또 외부 상용 AI에 군 관련 정보를 보내려면 **보안 승인**이 필요하다.

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | 인트라넷 PC에서 직접 호출 (예외 허용 승인) | 흐름이 가장 단순 | 승인 가능성이 낮음 |
| B | **인터넷 PC에서 민간 공개 기상 수치만으로 조언 생성 → 결과를 망연계로 반입** | 승인 부담이 적음, 공개 정보만 사용 | 공군 전문 반영 불가, 반입 단계 추가 |
| C | 국방망 내부에서 승인된 AI로 대체 (모듈 교체) | 보안상 가장 안전 | 해당 AI 존재 여부 확인 필요 |

> 시제품은 **어느 안이든 쓸 수 있게** 만든다. 모듈은 같은 코드로 인터넷 PC(안 B)에서도 동작하고, 엔드포인트만 바꾸면 안 C로 전환할 수 있다.

### 16-3. 보내는 데이터 (허용 목록 방식)
- **보냄**: 회차, 지형 구분(육상/산지), 기상 수치(기온, 체감, 강수, 적설, 풍속, 돌풍, 시정, 운고, PM10, 하늘, 현상, 시간대별 값), 발령 특보 종류·단계, 규칙 엔진의 활동명·판정·근거
- **보내지 않음**: 부대명, 위치·좌표, 병력, 훈련 일정, 작성자, 전문 원문, 캡처 이미지, 메모
- 호출 전에 **전송 미리보기**로 실제 보낼 JSON을 보여주고 확인 후 전송한다

### 16-4. 구현 사양
| 항목 | 내용 |
|---|---|
| 모듈 | `gemini_advisor.js` (단일 HTML에 인라인 포함) |
| 엔드포인트 | `POST https://generativelanguage.googleapis.com/v1beta/models/{모델}:generateContent` |
| 인증 | `x-goog-api-key` 헤더 (Google AI Studio에서 발급) |
| 기본 모델 | `gemini-2.5-flash` (설정에서 변경, 도입 시 최신 모델명 확인) |
| 출력 | JSON 강제 (`responseMimeType: application/json` + `responseSchema`) |
| 온도 | 0.2 (일관성 우선) |
| 시간 제한 | 20초, 넘으면 규칙 결과로 대체 |
| 키 저장 | 해당 PC 브라우저 localStorage, HTML 파일에는 넣지 않음 |

### 16-5. 화면 반영
- **이력 화면 > 설정 탭**: AI 사용 켜기/끄기, API 키 입력·삭제, 모델명, [연결 테스트]
- **브리핑 화면**: [AI 조언 받기] 버튼 → 전송 미리보기 → 결과 표시
  - AI 요약, 주요 위험 카드
  - 활동별 표에 출처 표시: `규칙` / `AI` / `AI 상향` (상향된 항목은 강조)
  - 하단에 "AI 조언은 참고용이며 최종 결심은 지휘관" 문구
- pptx와 인쇄물에 AI 요약 포함 여부 선택
- 이력에 AI 응답, 모델명, 생성 시각 함께 저장

### 16-6. 완료 기준 (추가)
- [ ] 설정에서 키를 넣고 [연결 테스트]가 성공한다 (인터넷 가능 PC 기준)
- [ ] [AI 조언 받기]로 20초 안에 요약과 활동별 건의가 표시된다
- [ ] AI가 규칙보다 낮은 단계를 제안해도 최종 단계는 규칙 결과로 유지된다 ✅ 모의 테스트 통과
- [ ] 전송 데이터에 부대명, 위치, 허용 목록 밖 필드가 포함되지 않는다 ✅ 모의 테스트 통과
- [ ] 네트워크 차단, 키 오류, 잘못된 응답에서도 규칙 결과로 브리핑이 완성된다 ✅ 모의 테스트 통과
- [ ] AI를 끈 상태에서 외부 통신이 전혀 발생하지 않는다

### 16-7. 사용자 준비 사항
1. **보안 담당 부서에 외부 AI 사용 가능 여부 문의** (16-2의 A/B/C 중 어떤 안이 가능한지)
2. Google AI Studio에서 API 키 발급 (개인 계정이 아닌 **승인된 계정** 권장)
3. 무료 등급은 입력 데이터가 모델 개선에 쓰일 수 있으므로 **유료 등급 약관과 데이터 처리 조건 확인**
4. 도입 시점의 최신 모델명과 요금 확인
